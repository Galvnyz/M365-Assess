# T-0361 — Defender policy-area registry and status API

## Report

EPIC-019 SPEC.md §2 US-1 and §3.1 define **Defender Status**: cards/table per policy area (AV, EDR,
ASR, compliance, firewall, exclusions) with current state vs recommended, reusing the module's
Defender assessment data (`src/M365-Assess/Security/Get-DefenderPolicyReport.ps1` and the
`Defender*Checks.ps1` collectors). §6 fixes `GET /v1/tenants/{id}/defender/status`. §11.2 is
resolved to **AV/EDR/ASR first**, with the other areas surfaced as future.

Deliver a `defender-policy-areas.ts` registry (mirroring EPIC-016's `intune-policy-types.ts`,
T-0301) enumerating each policy area, its source (Graph security / device management / EXO), and
required scopes; a read-only `Get-DefenderStatus.ps1` + `get-defender-status.ps1` worker that
runs the module's existing Defender checks read-only and returns current vs recommended; and the
BFF route behind RBAC `defender.read`. No `src/M365-Assess/` file is modified.

## Acceptance

- [ ] `GET /v1/tenants/{id}/defender/status` returns current vs recommended per policy area.
- [ ] The registry enumerates AV/EDR/ASR as v1 areas and marks the rest as not-yet-supported.
- [ ] The worker is read-only and reuses the existing module Defender checks; no `src/` file changes.
- [ ] Tests cover the registry and route and fail without them.
- [ ] No file outside `scope` is modified.
