# T-0811 — Request pipeline: JSON bodies and caller resolution

## Report

`buildServer` hands each route a `RequestContext` of correlation id, method, path, query,
headers, and params — nothing else. Two things every feature route depends on are missing:

- **Request bodies are never read.** Routes read `ctx.body` for every POST/PATCH/DELETE (the
  T-0305 seam comment says "until `RequestContext` carries a parsed `body`"), so every write
  endpoint currently sees `undefined`.
- **Nobody is authenticated.** `auth/identity.ts` defines `IdentityProvider.authenticate(request)`
  (with `BearerIdentityProvider` and the T-0748 API-client provider), but the server never calls
  it. Routes take a synchronous `resolveCaller(ctx)`, which has nothing to read.

Extend the pipeline:

1. Parse `application/json` bodies onto `ctx.body` before dispatch, with a size limit (1 MiB):
   invalid JSON → 400 `request.validation_failed`, oversize → 413. Non-JSON bodies are left unset.
2. Accept an optional `identity: IdentityProvider` in `BuildServerOptions`; when present,
   authenticate each request and attach the result as `ctx.caller` (`null` when anonymous). A
   provider error is a 401, never a 500. Routes' `resolveCaller` can then be `(ctx) => ctx.caller`.
3. Add `body?: unknown` and `caller?: PortalUser | null` to `RequestContext`, so the per-route
   `…RequestContext extends RequestContext { body?: unknown }` casts become unnecessary.

Authorization stays per route (the composition root passes an authorizer, T-0817); this ticket
only establishes who the caller is.

## Acceptance

- [ ] JSON bodies reach `ctx.body`; invalid JSON is a 400 and oversize a 413 with the standard error body.
- [ ] With an identity provider configured, `ctx.caller` is the authenticated user or `null`; provider failures are 401.
- [ ] Bearer tokens are never logged or placed on the context.
- [ ] Tests cover body parsing, limits, and caller resolution and fail without them.
- [ ] No file outside `scope` is modified.
