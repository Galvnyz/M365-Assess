# T-0831 — PIM request approval is not connected to Entra

## Report

`POST /v1/tenants/:tenantId/pim/requests` now submits through `new-pim-request.ps1` (T-0818),
which posts a `roleAssignmentScheduleRequest` to Graph. When the role's Entra policy requires
approval, Graph returns `PendingApproval` and Entra's own approvers decide. The portal's
`POST .../pim/requests/:id/transition` route, however, only updates the portal record: marking
a request `approved` or `active` there does not approve it in Entra, and a request approved or
denied in Entra never updates the portal record. The two states drift.

Two further points need a live tenant:

- `activate` and `deactivate` map to Graph's `SelfActivate`/`SelfDeactivate`, which act for the
  signed-in principal. The workers sign in app-only, so these likely fail and need
  `AdminAssign`/`AdminRemove` on an active schedule instead.
- `extend` sends `AdminExtend` with a duration counted from now rather than from the current end.

## Acceptance

- [ ] A decision is recorded on whether approval happens in Entra (portal mirrors it) or in the portal (portal approves through Graph).
- [ ] The transition route and request state follow that decision, with tests.
- [ ] Each request action is verified against a live tenant, or the ticket records that it waits on one (see T-0814).
