# T-0814 — Verify EPIC-016 Graph calls against a live tenant

## Report

Every EPIC-016 worker test mocks `Invoke-MgGraphRequest`, so these Graph assumptions were never
exercised:

- **API version.** The T-0301 registry points configuration (settings catalog) policies at
  `v1.0/deviceManagement/configurationPolicies`; settings-catalog policies are believed to be
  beta-only. Workers use `/beta` for `reusablePolicySettings` and `assignmentFilters`.
- **Update verbs.** `Deploy-IntuneTemplate` uses `PUT` for settings-catalog updates and `PATCH`
  for compliance; `Sync-ReusableSettings` uses `PUT`; `Set-AssignmentFilter` uses `PATCH`.
- **Payload shape.** Compliance creates get a default `scheduledActionsForRule` block action
  (Graph rejects creation without one); template deploy strips read-only fields; assignments
  post to `{resource}/{id}/assign` with `{ assignments: [...] }`.
- **Reusable-settings scope.** The v1 sync scope identifies types by the
  `settingDefinitionId` prefixes `vendor_msft_firewall_mdmstore_dynamickeywords_addresses_`
  and `device_vendor_msft_defender_configuration_devicecontrol_policygroups_`.
- **Assignment-filter platforms.** The registry maps windows/android/ios/macos to
  `windows10AndLater`/`androidForWork`/`iOS`/`macOS`.

Run each worker against a test tenant, correct any wrong endpoint, verb, or payload, and update
the mocked tests to the real response shapes observed. A person must run this; the agent has no
tenant credentials.

## Acceptance

- [ ] Each listed assumption is confirmed or corrected against a live tenant, with the result recorded in this ticket.
- [ ] Registry Graph resources match the API version each type actually exists in.
- [ ] Worker tests reflect observed response shapes; they fail without any corrections made.
- [ ] No file outside `scope` is modified.
