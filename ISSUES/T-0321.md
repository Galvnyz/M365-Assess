# T-0321 — Intune app-type registry and app / detected-app list API

## Report

EPIC-017 SPEC.md §2 US-1 and §3.1 require an app catalog table (Name · Type · Platform ·
Assigned · Install state · Last modified) plus a detected-apps view with a "Create app from
detected" action. §6 fixes `GET /v1/tenants/{id}/apps` for both the catalog and the detected
view.

Deliver a read-only `Get-IntuneApps.ps1` worker handler + `get-intune-apps.ps1` entrypoint
(rehydrating the EPIC-001 RunContext), an `intune-app-types.ts` registry mirroring EPIC-016's
`intune-policy-types.ts` (T-0301), and the BFF route behind the RBAC `intune.apps` seam (T-0013).
Per §11.1 the registry supports **Win32 and Store apps for v1**; other types (Office/Edge/MSP/
Choco) return a structured "not yet supported" error rather than an empty list. Per §11.4 the
detected-apps source is Graph **discovered apps** read directly (a reporting cache is deferred).

## Acceptance

- [ ] `GET /v1/tenants/{id}/apps` lists apps with type, platform, assignment count, and modification info.
- [ ] The detected-apps source reads Graph discovered apps; an unsupported app type is reported, not silently dropped.
- [ ] The handler is read-only; the T-0015 guard test still passes.
- [ ] A test covers the registry and route and fails without them.
- [ ] No file outside `scope` is modified.
