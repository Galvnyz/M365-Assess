# T-0812 — Apply the Intune policy list filters in the worker

## Report

EPIC-016 SPEC.md §3.1 fixes the policy-list filters: platform, type, assignment, and modified
date. The T-0301 route accepts `platform`, `policyType`, `assigned`, `modifiedDate`, and `search`
and hands them to the worker, but `Get-IntunePolicies`:

- reads `platform`, `policyType`, and `modifiedDate` in `Read-IntunePoliciesJob` and never uses them;
- does not read `assigned` at all;
- applies only `search`, and `get-intune-policies.ps1` passes only `-Search`.

The T-0303 table currently re-filters loaded rows client-side, which hides the gap for one page
of results but not across pagination.

Apply every filter in the worker (after row conversion, so it matches the portal's `platform`,
`policyType`, and `assignedToCount` values), treat `modifiedDate` as "modified on or after this
day" (the T-0303 UI's meaning), and pass all filters through the entrypoint. Apply filters
before paging so `nextCursor` stays consistent.

## Acceptance

- [ ] platform, policyType, assigned, modifiedDate, and search each narrow the worker's results.
- [ ] The entrypoint passes every filter from the job envelope.
- [ ] Paging applies after filtering.
- [ ] Pester tests cover each filter and fail without it.
- [ ] No file outside `scope` is modified.
