# T-0835 — Build and render generated reports

## Report

The reports routes (EPIC-005) record a generated report and hand a render job to a queue;
`render-report.ps1` prints an HTML file to PDF with headless Chromium. Nothing produces that HTML:
no code turns an executive payload (`RunReadPort.executivePayload`) or a report-builder template
document into a page. T-0823 therefore mounts the render ports as 501 `report.render_unavailable`
(a report already recorded is marked failed first).

Two further gaps sit on the same path:

- `GET /v1/reports/:id/download` returns the `artifactRef` for "the serving layer" to stream, and no
  serving layer exists; it should stream the PDF (tenant-scoped, audited) like run artifacts.
- The executive payload has only tenant facts and the run's summary counts; secure score and action
  buckets are empty, and the counts stay empty until T-0833 records findings.

## Acceptance

- [ ] A decision records where report HTML is composed, from both the executive payload and a template document.
- [ ] Generating a report writes the HTML, runs `render-report.ps1` through the job queue, and moves the report to succeeded with its PDF `artifactRef`, or failed with the reason.
- [ ] Download streams the PDF for callers in the report's tenant scope and records the download.
- [ ] Tests cover a render through a fake worker and a download.
