# T-0830 — Merge Entra directory audits into CA change history

## Report

EPIC-015 SPEC §4.4 and §11.4 resolve CA change history to use both sources: Entra directory
audits for provenance (changes made outside the portal) plus the portal's own before/after
records. `GET /v1/tenants/:tenantId/ca/history` (T-0819) serves only the portal half, from
`audit_events` rows for `ca.policy.*` and `ca.template.deploy`, because no worker reads
directory audits. Changes made in the Entra admin center, by other tools, or by Microsoft never
appear.

Add a read-only worker that queries `auditLogs/directoryAudits` filtered to the Conditional
Access policy activities (add, update, delete policy) for the tenant, optionally for one policy
id, and returns records in the `CaPolicyChangeRecord` shape with `source: "directoryAudit"`.
The adapter merges them with the portal rows: a portal row and a directory audit for the same
policy within a short window collapse into one `source: "merged"` record that keeps the
portal's before/after and the audit's `initiatedBy`.

## Acceptance

- [ ] A worker returns directory-audit CA policy changes for a tenant (and one policy when asked), with Pester tests against mocked Graph responses.
- [ ] `getHistory` merges both sources, newest first, marking each record `portal`, `directoryAudit`, or `merged`.
- [ ] Adapter tests cover the merge, including a change that exists only in directory audits.
- [ ] Live verification against a tenant is recorded, or the ticket notes it waits on one (see T-0814).
