# T-0817 — Composition root: mount the repository-backed routes

## Report

`index.ts` calls `buildServer()` with no routes, so no feature endpoint is served. Build
`app.ts`, the composition root, and mount the routes that need no worker: EPIC-001 through
EPIC-010 (health, tenants, runs, dashboards, reports, remediation, schedules, standards, drift,
baselines), EPIC-019 (Defender templates and CVE exceptions), and EPIC-038 (API clients).

- One SQLite database; construct each SQLite repository/store from it.
- The T-0748 and bearer identity providers passed to `buildServer` (T-0811); every route's
  `resolveCaller` reads `ctx.caller`.
- One authorizer built on `requirePortalAccess` (T-0743), passed to **every** route's
  `authorize` option so no route falls back to its permissive "no permissions resolved" default.
- One audit sink for routes that take `recordAudit`.
- `permissions.test.ts`'s hand-written `mountedEndpoints()` replaced by the app's real route list.

Worker-backed routes are mounted by T-0818 to T-0820 through the same root.

## Acceptance

- [ ] `index.ts` serves the listed epics' routes through `app.ts`.
- [ ] Every mounted route receives the portal-access authorizer; a `readonly` caller is refused a write route and allowed a read route.
- [ ] The permission completeness test runs against the app's real route list, and `PermissionRegistry` lists every mounted endpoint (moved here from T-0816).
- [ ] The authorizer reconciles the EPIC-001 run permissions (`runs.*`, `admin`, checked via `rbac/roles.ts` admin/operator) with the EPIC-038 base roles, so both portal users and API clients are authorized one way.
- [ ] Tests fail without the composition root.
- [ ] No file outside `scope` is modified.
