# T-0816 — Align route permission strings with the EPIC-038 taxonomy

## Report

EPIC-038 SPEC §11 item 2 fixes the permission taxonomy as `{Area}.{Resource}.{Action}`, and the
T-0741 base roles grant by pattern: `readonly` includes `*.Read`, `editor` `*.Read` and
`*.ReadWrite`, `admin`/`superadmin` `*`. `matchesAccessPattern` is case-sensitive. The feature
routes instead check about 36 ad-hoc lowercase strings — `intune.read`, `intune.write`,
`intune.templates`, `ca.deploy`, `groups.templates`, `drift.triage`, `devices.keys`, … — so once
real authorization is wired (T-0817), only `admin` and `superadmin` could use any feature route;
`readonly` and `editor` would be refused everywhere.

Rename every route permission constant to the taxonomy with `Read` / `ReadWrite` actions (e.g.
`Intune.Policy.Read`, `Intune.Policy.ReadWrite`, `Intune.Template.ReadWrite`,
`ConditionalAccess.Template.ReadWrite`), keeping sensitive reads distinct where the SPEC asks
(e.g. `Device.Keys.Read` for BitLocker/LAPS), and register each endpoint's permission in
`PermissionRegistry`. Add a test that every registered permission is granted to `editor` or
`readonly` by the matching action, except the documented admin-only areas.

## Acceptance

- [ ] Every route permission matches `{Area}.{Resource}.{Read|ReadWrite}` (or a documented admin-only permission).
- [ ] `readonly` is granted every `.Read` route permission and `editor` every `.ReadWrite` one via `testPortalAccess`.
- [ ] The permission registry lists every route endpoint with its new permission.
- [ ] Tests fail without the rename.
- [ ] No file outside `scope` is modified.
