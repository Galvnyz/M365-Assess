# T-0841 — Run standards, drift, and baseline jobs

## Report

T-0825 mounts the EPIC-008, EPIC-009, and EPIC-010 routes on persistent storage, but the jobs that
fill that storage have no worker entrypoint. `Invoke-Standard.ps1`, `Invoke-Drift.ps1`, and
`Invoke-Baseline.ps1` exist as module functions with injectable seams only, and the job dispatcher
(T-0836) has no runner for `standards`, `drift`, or `baseline` envelopes. As a result:

- `POST /v1/standards/templates/:templateId/run` refuses with 501 (`createUnavailableStandardsRunQueue`),
  and nothing writes `standard_compare` rows, so the alignment and compare views stay empty.
- `POST /v1/drift/:tenantId/refresh` refuses with 501 (`createUnavailableDriftRefresh`), and nothing
  upserts drift deviations.
- A deny that deletes (single deny, bulk `deny-delete`) refuses with 501 through `refuseDriftDeletion`
  before any triage write. The route writes `denied`/`deletePending` before it queues the delete, so
  its remediation port must work before that guard is removed; the delete itself runs as a
  remediation apply job (T-0838).
- No baseline evaluation writes rollouts, history, or trend points; only the advance route does.
- The standards run route's `resolveVariables` is not wired, so tenant variables are not substituted.

## Acceptance

- [ ] Standards, drift, and baseline envelopes each dispatch to a worker entrypoint that calls the existing module function, with its seams bound to real storage.
- [ ] A standards run records `standard_compare` rows (`upsertCompare`); drift refresh upserts deviations, preserving triage; a baseline evaluation writes rollouts, history, and trend points.
- [ ] Standards run-now and drift refresh enqueue jobs instead of refusing with 501; the standards run resolves tenant variables.
- [ ] Deny-for-deletion queues its delete once T-0838 lands, and `refuseDriftDeletion` is removed.
- [ ] Pester tests cover each entrypoint; app tests cover run-now and refresh through the server.
