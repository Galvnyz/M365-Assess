# T-0826 — Feature workers connect to their tenant

## Report

Every feature worker (34 entrypoints under `portal/workers/`) calls `Invoke-MgGraphRequest`, and
three also use Exchange Online cmdlets, but none connects first: only the assessment path
(`run-tenant.ps1` → `Invoke-M365Assessment`) signs in. `Resolve-TenantCredential` (T-0011)
already turns a credential reference plus its non-secret row into auth material inside the child
process, and `Test-TenantConnection` shows the connect pattern through the module's
`src/M365-Assess/Common/Connect-Service.ps1`.

Add `Connect-WorkerTenant`: read the job file's `credential` block (`credentialRef` and the
non-secret `record` the BFF includes), resolve it with `Resolve-TenantCredential`, connect the
services the worker declares (Graph by default; Exchange Online for the three EXO workers) via
`Connect-Service.ps1`, and return a disconnect action. Every Graph/EXO entrypoint connects after
reading its job and disconnects in `finally`. Errors are coded and never contain secret material
(`Protect-WorkerSecret`). A job without a `credential` block fails with a clear code rather than
running unauthenticated. Secret-backed credentials still need T-0827's backend; thumbprint
credentials work without it.

## Acceptance

- [ ] `Connect-WorkerTenant` resolves the job's credential and connects the requested services, returning a disconnect action.
- [ ] Every Graph- or EXO-calling feature entrypoint connects before work and disconnects in `finally`.
- [ ] Missing or mismatched credential blocks fail with a coded error; secrets never appear in messages.
- [ ] Pester tests cover the function (with Connect-Service and the resolver mocked) and a convention check over the entrypoints, and fail without the change.
- [ ] No file outside `scope` is modified.
