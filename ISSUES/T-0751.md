# T-0751 — OpenAPI 3.1 publication at /openapi.json

## Report

EPIC-038 SPEC.md §3.5 and §6: `GET /openapi.json` serves the generated OpenAPI 3.1 document, and
a read-only docs page renders it with an auth primer (client credentials against
`api://<appId>/.default`). The document must validate as OpenAPI 3.1 and list every endpoint
(SPEC §10).

**This ticket owns the OpenAPI document.** Per EPIC-001 SPEC.md §1, route tickets declare their
path items and permission as metadata in their own route module and do **not** hand-edit the
shared document; this ticket assembles `portal/contracts/openapi/portal.v1.yaml` and
`/openapi.json` from that route metadata, so the spec cannot drift from the implementation. Add
`openapi.ts` to generate and serve the document, and the read-only `api-docs/page.tsx` that
renders it with the auth primer. Route tickets already mounted (T-0744, T-0745, T-0747, T-0750)
contribute their metadata; the generator must fail if a mounted endpoint declares none.

## Acceptance

- [ ] `portal.v1.yaml` and `/openapi.json` are generated from route metadata; no route ticket
      hand-edits them.
- [ ] Generation fails when a mounted endpoint lacks a path item or permission declaration.
- [ ] `/openapi.json` validates as OpenAPI 3.1 and lists every mounted endpoint.
- [ ] The docs page renders the spec read-only with the client-credentials auth primer.
- [ ] The served document and the checked-in `portal.v1.yaml` do not drift (asserted by test).
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
