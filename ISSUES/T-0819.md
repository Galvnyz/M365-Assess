# T-0819 — Mount the Groups and Conditional Access routes with worker-backed providers

## Report

The route modules for EPIC-014, EPIC-015 (groups and Conditional Access: `groups-*.ts group-templates*.ts ca-*.ts` under `portal/bff/src/routes/`) take provider
interfaces that run PowerShell workers, and nothing implements them. Add the providers under
`portal/bff/src/providers/`, each built on `runFeatureWorker` (T-0815): translate the route's
typed call into the worker's job envelope (tenant id, action, inputs, actor), run the matching
`portal/workers/*.ps1` entrypoint, and map its JSON back to the provider's return type. Mount
the routes in `app.ts` with the shared repositories, `ctx.caller`, the portal-access
authorizer, and the audit sink from T-0817.

## Acceptance

- [ ] Every EPIC-014, EPIC-015 route module is mounted with a worker-backed provider.
- [ ] A test per provider runs it against a fake worker runner and checks the envelope sent and the result mapping.
- [ ] An app-level test reaches at least one read and one write route per epic through the server.
- [ ] No file outside `scope` is modified.
