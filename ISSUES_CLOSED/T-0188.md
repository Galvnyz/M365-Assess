# T-0188 — Baseline history, run events, and trend sampling

## Report

EPIC-010 SPEC.md §4.5 (US-5, US-6) makes `BaselineHistory` **append-only** and feeds periodic
`BaselineTrend` points to the fleet chart; §5 defines both entities. §3.1's **Fleet Compliance
Trend** is a hand-rolled SVG chart. Resolved §11.5 adopts **per-run trend sampling with display
downsampling**. §9 rates "history volume" a risk mitigated by retention per
[`03-database.md`](../../docs/portal-specs/00-guides/03-database.md) §7.

Deliver the history/trend domain, migration `0012`, the run-events API under
`GET /v1/baselines/{id}/alignment`, and `FleetTrendChart`. Every evaluation (T-0185) appends one
history row and one trend point; the chart downsamples for display. History rows are never
mutated or deleted except by retention pruning.

## Acceptance

- [x] Every baseline evaluation appends a `BaselineHistory` event and a `BaselineTrend` point.
- [x] History is append-only; retention pruning follows the configured window.
- [x] The fleet trend chart downsamples points for display and renders from the API.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
