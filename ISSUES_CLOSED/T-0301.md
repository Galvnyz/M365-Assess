# T-0301 — Intune policy-type registry and policy list API

## Report

EPIC-016 SPEC.md §3.1 defines three list pages (Configuration, Compliance, App Protection) with
columns Name · Platform · Type · Assigned to · Last modified · Modified by and filters platform,
type, assignment, modified date. §6 fixes `GET /v1/tenants/{id}/intune/{kind}` where `kind ∈
{configuration, compliance, app-protection}`. §9 warns of Graph **policy-type proliferation** and
requires a shared policy-type registry with tests covering each type. §11.1 is resolved to
**Windows configuration + compliance policies first**, other types later.

Deliver a read-only worker handler `Get-IntunePolicies.ps1` + entrypoint (rehydrating the
EPIC-001 `RunContext`) that lists policies per `kind`, plus the shared
`intune-policy-types.ts` registry and the BFF route behind the RBAC seam (T-0013). The registry
maps each supported `kind`/platform to its Graph resource, required scopes, and settings
shape, and drives both the list handler and the later CRUD/editor tickets. v1 supports Windows
configuration and compliance; unsupported types return a structured "not yet supported" error
rather than an empty list.

## Acceptance

- [x] `GET /v1/tenants/{id}/intune/{kind}` lists policies with platform, type, assignment count, and modification info.
- [x] A shared policy-type registry enumerates supported kinds and is covered by a test per type.
- [x] Windows configuration and compliance are supported; other types are reported as unsupported.
- [x] The handler is read-only; the T-0015 guard test still passes.
- [x] No file outside `scope` is modified.
