# T-0165 — Accept and customer-specific override triage

## Report

EPIC-009 SPEC.md §3.2 and §4.2 define two triage paths. **Accept deviation** records a reason and
expiry; if *remediate automatically when the acceptance expires* is set, the deviation becomes
remediable when it lapses (US-3). **Create tenant override** records a tenant-specific expected
value so future runs treat the item as compliant; **Remove tenant override** reverts to the
template value (US-4). §6 fixes `POST /v1/drift/deviations/{id}/accept` and
`.../override`.

Deliver the triage endpoints and `drift-triage.ts`. Accept sets state `accepted` (no action until
expiry) and persists `reason`, `expiresOn`, `autoRemediateOnExpiry`. Override sets state
`customerSpecific` and stores `overrideValue`; the drift upsert (T-0162) must then treat the item
as compliant. Writes require `drift.triage` (prose: EPIC-001 T-0013 RBAC seam).

## Acceptance

- [x] Accept records reason/expiry and sets state `accepted`; expiry with auto-remediate becomes remediable.
- [x] Override stores a tenant value so a later drift run treats the item as compliant; remove reverts it.
- [x] Missing `drift.triage` returns a structured error; the action is audited.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
