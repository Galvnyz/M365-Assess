# T-0222 — Reset MFA, single and gated bulk

## Report

EPIC-012 SPEC.md §3.2 and §4.2 (US-2): **Reset MFA** removes authentication methods and requires
re-registration; it is a gated tenant write routed through EPIC-006 (confirm, apply, audit).
§3.1 lists **requiring re-registration** and **send push** as bulk actions. §11.1 resolves bulk
reset MFA as **allowed but gated and audited, with an explicit batch confirmation.**

Add `POST /v1/tenants/{id}/users/{userId}/mfa/reset` and a bulk variant to `mfa.ts`, and the
`Reset-UserMfa.ps1` worker job plus `reset-user-mfa.ps1` entrypoint. Single and bulk both route
through the EPIC-006 apply/audit path (T-0107/T-0108); bulk requires the same explicit batch
confirmation as T-0113's apply dialog (count shown, reason required). Lockout risk (§9) is
mitigated by confirmation and audit — never reset without it.

## Acceptance

- [x] Single reset removes the user's methods and returns the post-reset method state.
- [x] Bulk reset requires an explicit batch confirmation and is audited per user.
- [x] Every reset writes an `AuditEvent`; no path resets without going through the gate.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
