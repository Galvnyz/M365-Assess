# T-0289 — Report-only evaluation surface

## Report

EPIC-015 SPEC.md §3.5 defines a page/panel showing what **report-only** policies *would* have
done (sign-in impact), so operators can safely promote them to enforced; §6 fixes
`GET /v1/tenants/{id}/ca/report-only`. §4.2's report-only recommendation and §8's report-only
default for new policies make this the safety valve for the §9 lockout risk.

Deliver a read-only worker handler `Get-CaReportOnly.ps1` + entrypoint and the route plus the
`ReportOnlyPanel`/page. The handler reads the report-only policies' sign-in impact from the
available signals (Graph sign-in logs / policy evaluation results) and summarises, per policy,
the users/apps that would have been affected and the grant/block decision that would have
applied. The surface is read-only; any "promote to enforced" action routes through the T-0282
edit path (link out, not an inline write).

## Acceptance

- [x] `GET /v1/tenants/{id}/ca/report-only` returns, per report-only policy, what would have been blocked/affected.
- [x] The page renders the impact summary; no inline write path is introduced.
- [x] Tests cover the route/handler and panel and fail without them.
- [x] No file outside `scope` is modified.
