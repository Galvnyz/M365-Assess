# T-0225 — Authentication methods policy with plan preview and v1 presets

## Report

EPIC-012 SPEC.md §3.3 and §4.3 (US-6): the **Authentication Methods** page configures per-method
enable/target with a **plan preview** before apply; §4.3 states policy writes are higher-risk
and require `Remediation.Apply`. §11.2 resolves v1 to **common presets** (for example
phishing-resistant-required, MFA-required, and standard) with the full per-method editor as a
later expansion. §5 allows an optional `AuthMethodPolicySnapshot` for the preview.

Add `GET`/`PUT /v1/tenants/{id}/auth-methods-policy` to `auth-methods-policy.ts`, a
`presets.ts` mapping each named preset to a concrete policy shape (with validation), and the
`Set-AuthMethodsPolicy.ps1` worker job plus `set-auth-methods-policy.ps1` entrypoint. The `PUT`
supports a preview mode returning current-vs-proposed diff and applies only through the EPIC-006
gate (T-0104) and gated executor (T-0107). Lockout risk is mitigated by the preview and audit.

## Acceptance

- [x] `GET` returns the current policy; `PUT` preview returns the current-vs-proposed diff with no write.
- [x] Each v1 preset maps to a validated concrete policy; an unknown preset is rejected.
- [x] Apply routes through the EPIC-006 gate/executor and is audited.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
