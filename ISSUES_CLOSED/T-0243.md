# T-0243 — PIM role settings templates CRUD and compare

## Report

EPIC-013 SPEC.md §3.2 and §5 (US-3): the **Templates** tab defines reusable role settings (max
duration, MFA required, justification, approval) with row actions `Edit`, `Clone`, `Apply to
role`, `Delete` and a **Compare** action showing current vs template. §5 defines
`PimRoleSettingsTemplate` (`id`, `name`, `roleId?`, `settings`, `scope`). §11.3 resolves the
granularity to **per role** (per role+scope is deferred).

Add the `PimRoleSettingsTemplate` entity via the next forward-only migration and a
`pim-settings-repository.ts`, then expose `GET`/`POST`/`PATCH`/`DELETE`
`/v1/pim-settings-templates` in `pim-settings-templates.ts`. Compare returns the stored template
aligned with the live role settings fetched through the T-0242 worker read; it performs no write.
Extend `portal.v1.yaml`.

## Acceptance

- [x] Templates CRUD persists name, optional role, settings, and scope and round-trips them.
- [x] Compare returns current-vs-template differences for a role without writing to the tenant.
- [x] Templates are per role for v1; a role+scope template is rejected as out of scope.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
