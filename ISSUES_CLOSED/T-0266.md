# T-0266 — Group template deploy worker and API

## Report

EPIC-014 SPEC.md §4.2 defines template deploy: resolve template + variables → plan (group +
owners + members + settings) → apply, per target, with **partial failures reported**. §5 adds the
`GroupTemplateDeployment` record (`id`, `templateId`, `tenantId`, `state`, `results[]`,
`createdBy`), and §6 fixes `POST /v1/group-templates/{id}/deploy`. §3.2's deploy wizard resolves
variables before deploy, and §11.2 requires conflict handling to be defined in the naming policy.

Deliver `Deploy-GroupTemplate.ps1` and its `deploy-group-template.ps1` entrypoint, plus the BFF
route behind the gated-write seam (T-0108). The worker resolves the template and variables into
an ordered plan, creates the group, then owners, members, and settings, recording a per-target
result row and partial-failure detail into `GroupTemplateDeployment`; every write is audited
(§8). Conflict handling follows the naming policy defined alongside the templates UI (T-0267):
when a resolved name collides, the plan reports the conflict and the deploy blocks rather than
silently renaming.

## Acceptance

- [x] Deploy resolves template + variables, returns a plan, and applies with per-target results.
- [x] Partial failures and name conflicts are reported per target rather than swallowed.
- [x] A `GroupTemplateDeployment` record is persisted and each write is audited.
- [x] Tests cover the worker and route and fail without them.
- [x] No file outside `scope` is modified.
