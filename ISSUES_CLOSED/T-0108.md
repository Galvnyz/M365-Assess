# T-0108 — Gated apply API with Idempotency-Key and audit trail

## Report

EPIC-006 SPEC.md §4.3, §6, §8 and
[`06-remediation.md`](../../docs/portal-specs/00-guides/06-remediation.md) §3.2/§5: apply is a
separate, higher-privilege operation. `POST /v1/remediation/plans/{planId}/apply` requires an
`Idempotency-Key` and a `dryRun` boolean, re-checks all gates (license/service/RBAC/scope/
read-only/allowlist), runs one action at a time via the executor (T-0107), and writes for every
action the command, `before`, `after`, actor, timestamp, and result to `RemediationAction` and
an append-only `AuditEvent`. SPEC.md §11 item 4 resolves batching as **stop-on-first-failure by
default, with an explicit override**. Only checks whose matrix `specStatus` is `approved`
(T-0110) are eligible. `GET /v1/remediation/history` serves the tenant-wide audit view, cursor
paginated (SPEC §3.4).

Add the `Invoke-RemediationApply.ps1` worker job + `apply-remediation.ps1` entrypoint, the BFF
apply route/domain (extend `remediation.ts` from T-0105), and the history endpoint; extend
`portal.v1.yaml`. `dryRun` must write nothing.

## Acceptance

- [x] Apply requires `Idempotency-Key`; a repeated key returns the prior result without re-executing.
- [x] `dryRun: true` writes no tenant state and no `applied` action.
- [x] Every applied action records command/before/after/actor/timestamp/result and an `AuditEvent`.
- [x] A failure stops the batch by default; an explicit override continues, and the failure is recorded.
- [x] A non-allowlisted or unapproved check is not applied.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
