# T-0823 — Mount the Dashboards and reports routes on real storage

## Report

The EPIC-004, EPIC-005 route modules (dashboard.ts, dashboard-layout.ts, reports.ts, report-templates.ts) take interfaces with no implementation: `DashboardRoutesStore`, `DashboardLayoutStore`, `GeneratedReportStore`, `RenderQueuePort`, `RunReadPort`, `AuditPort`, `ReportTemplateStore`, and the template render port. The
`@m365-assess/db` repositories hold the data but expose different method shapes, and the BFF does
not yet depend on that package.

Add `@m365-assess/db` as a BFF dependency if it is not already present, write adapters under
`portal/bff/src/adapters/` that implement each interface on top of the db repositories (or the BFF's
own repositories where the entity lives there), and mount the routes in `app.ts` with the T-0817
authorizer, caller resolution, and audit sink. Adapters translate shapes only — no domain logic
(ADR-0014 thin BFF).

## Acceptance

- [x] Every EPIC-004, EPIC-005 route module is mounted on adapters over persistent storage (no in-memory fakes).
- [x] Each adapter has a test against a real in-memory SQLite database.
- [x] An app-level test reaches at least one read and one write route per epic through the server with the authorizer applied.
- [x] No file outside `scope` is modified.

## Resolution

- Dashboards: the db dashboard and layout repositories already implement the route stores; the
  layout routes are mounted ahead of `/v1/dashboard/:tenantId`, which would capture `/layout`.
- Report templates: the db repository implements the store; the contract is
  `parseReportTemplate` (now exported as `@m365-assess/contracts/reports`).
- Reports (`adapters/reports.ts`): a generated-report store over the tenant-keyed repository
  (reports without a tenant are refused, since the table requires one; route and table statuses
  are translated), and a run reader for the latest finished run and its artifact files.
- Rendering is not built: nothing composes report HTML for `render-report.ps1`. The render ports
  refuse with 501 `report.render_unavailable`, failing any report already recorded. Filed T-0835.
- Scope additions (fixes found while wiring):
  - Neither reports module checked tenant scope: any caller with the permission could list,
    download, bundle, and generate reports, and read and edit report templates, for every tenant.
    Both now hide out-of-scope tenants from lists and refuse them elsewhere; reports and templates
    without a tenant stay open to holders of the permission.
  - db: migration 0080 creates `report_templates` in the shared database (its DDL only ran when
    the repository opened its own file). The dashboard, layout, report, and report template
    repositories are exported.
  - The dev identity now has a `portal_users` row, which per-user tables such as dashboard layouts
    reference; saving a layout failed a foreign key without it.
