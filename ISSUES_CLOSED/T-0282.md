# T-0282 — CA policy CRUD with plan preview and guardrail validation

## Report

EPIC-015 SPEC.md §4.1 requires create/edit via the editor → **plan preview (JSON diff)** → apply,
and §8 makes CA writes the highest-risk category: mandatory plan preview, explicit confirmation,
before/after capture, and audit; deleting an enforced policy requires explicit confirmation
naming the policy. §3.3 requires the editor to **validate against the same checks `CAEvaluator`
uses** (e.g. admin-role targeting, exclusion correctness) and warn on known-weak configurations
before save. §4.3 and §9 require warning on a policy that targets `All users` with no admin
exclusion (matching the module's `Test-ExcludesAdminRole`) and surfacing the security-defaults
conflict; §11.2 is resolved to **hard-block deploy on `All users` + `Block` without a break-glass
exclusion**. §11.1 resolves to **report-only as the default state for new policies**.

Deliver `Set-CaPolicy.ps1` + entrypoint, the shared validation module `ca-policy-validation.ts`
(compiling the §3.3/§4.3 checks including the hard-block), and the CRUD routes behind the T-0108
gated-write seam. Create/edit return a JSON diff plan; apply captures before/after and audits.
`POST` defaults to report-only unless the caller explicitly opts into enforced.

## Acceptance

- [x] Create/edit/delete return a JSON diff plan, capture before/after, and audit each write.
- [x] `All users` + `Block` without a break-glass exclusion is hard-blocked; `All users` with no admin exclusion warns.
- [x] New policies default to report-only unless enforced is explicitly requested.
- [x] Deleting an enforced policy requires a naming confirmation.
- [x] Tests cover the validation module and routes and fail without them.
- [x] No file outside `scope` is modified.
