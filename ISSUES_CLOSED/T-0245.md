# T-0245 — Role change requests with native pending-approval state

## Report

EPIC-013 SPEC.md §3.3 and §4.3 (US-4): submit an activation/assignment request for a window; a
justification is required and, where configured, the request enters a **pending state** tracked
until approval/activation, after which the assignment is active for the window. Requests are
audited and reflected in the assignments view. §5 defines `RoleChangeRequest` (`id`, `tenantId`,
`principalId`, `roleId`, `action`, `state`, `justification`). §11.1 resolves approvals to
**native pending state first; external PSA/Teams integration later.**

Add the `RoleChangeRequest` entity via the next forward-only migration and a
`role-requests-repository.ts`, and `POST /v1/tenants/{id}/pim/requests` in `pim-requests.ts`
plus a read of request state. The `New-PimRequest.ps1` worker job submits to Graph; a
justification is mandatory and an approval-required request is persisted as `pending` and later
transitioned. Extend `portal.v1.yaml`.

## Acceptance

- [x] A request without justification is rejected; a valid request is persisted and submitted.
- [x] When approval is configured the request enters `pending` and can transition to active/rejected; otherwise it activates directly.
- [x] Request state is reflected in the assignments view and each transition is audited.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
