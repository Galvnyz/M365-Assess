# T-0129 — Scheduler UI (tasks, task detail, system timers)

## Report

EPIC-007 SPEC.md §3.1 defines the **Scheduler** page: tabs **Scheduled Tasks / Task / Job**; a
table with Name · Target · Command · Schedule (cron, human readable) · State · Last run · Next
run · Enabled; filters (state, type, tenant, enabled) with presets Running / Planned / Failed /
Completed; row actions `View task`, `Edit`, `Run now` (confirm), `Enable/Disable`, `Clone`,
`Delete`; primary button `Add task`. §3.1 also requires a read-only **system timers** section.
§3.2 gives the task detail tabs Definition / History / Parameters. §3.4 reuses EPIC-003's
`QueueTracker` for job progress.

Deliver:

- Scheduler routes and components using report tokens (`02-ui-design.md` §6).
- `ScheduledTasksTable` with the columns, filters/presets, and row actions wired to T-0124.
- `SystemTimersCard` rendering the T-0123 registry read-only (no edit/delete affordances).
- Task detail page with Definition / History / Parameters tabs.
- Component tests with a stubbed API.

Note: `QueueTracker` itself is EPIC-003's component (prose cross-ref); this ticket consumes it.

## Acceptance

- [x] The tasks table renders all specified columns, filters, and row actions.
- [x] `Run now`, `Enable/Disable`, `Clone`, and `Delete` call the correct API.
- [x] System timers render with no edit or delete controls.
- [x] Cron renders as a human-readable description.
- [x] No file outside `scope` is modified.
