# T-0820 — Mount the Intune and devices routes with worker-backed providers

## Report

The route modules for EPIC-016, EPIC-018 (Intune policies, templates, reusable settings, assignment filters, compare, and device actions: `intune-*.ts device-*.ts` under `portal/bff/src/routes/`) take provider
interfaces that run PowerShell workers, and nothing implements them. Add the providers under
`portal/bff/src/providers/`, each built on `runFeatureWorker` (T-0815): translate the route's
typed call into the worker's job envelope (tenant id, action, inputs, actor, and the tenant's `credential` block from the T-0822 credential rows for T-0826's `Connect-WorkerTenant`), run the matching
`portal/workers/*.ps1` entrypoint, and map its JSON back to the provider's return type. Mount
the routes in `app.ts` with the shared repositories, `ctx.caller`, the portal-access
authorizer, and the audit sink from the T-0817 core.

## Acceptance

- [x] Every EPIC-016, EPIC-018 route module is mounted with a worker-backed provider.
- [x] A test per provider runs it against a fake worker runner and checks the envelope sent and the result mapping.
- [x] An app-level test reaches at least one read and one write route per epic through the server.
- [x] No file outside `scope` is modified.

## Resolution

- `adapters/intune.ts` implements the policy list, CRUD, template deploy, reusable settings, assignment
  filter, compare, BitLocker, and LAPS providers on `runFeatureWorker`, sending the tenant's credential
  block; worker failures become 502s with the first diagnostic line, a missing credential a 409.
- `adapters/audit.ts` records worker audit events in `audit_events` via the db repository.
- Mounted in `app.ts` with compare, reusable settings, and assignment filters ahead of the generic
  `/intune/:kind` routes (first match wins); registry entries added in the same order.
- `guardRoute` enforces permission and tenant scope for the device routes: the history route did no
  authorization at all, and the BitLocker/LAPS routes checked permission but not tenant scope.
- Worker changes (scope addition): `Get-IntunePolicyDetail` plus a `policyId` job field for compare,
  and the deploy worker now records the acting user.
- `guard.test.ts` now allows worker entrypoint file names (`set-*.ps1`) while still rejecting Set-*
  cmdlet names.
- Follow-up filed: T-0829 (the T-0304 editor never receives existing settings).
