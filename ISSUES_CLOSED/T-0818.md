# T-0818 — Mount the Identity routes with worker-backed providers

## Report

The route modules for EPIC-011, EPIC-012, EPIC-013 (users, offboarding, BEC, MFA and authentication methods, roles, PIM, and JIT: `offboarding.ts bec.ts users.ts user-templates.ts auth-methods-policy.ts mfa.ts registration-campaign.ts roles.ts pim.ts pim-requests.ts pim-settings-templates.ts jit-grants.ts jit-templates.ts` under `portal/bff/src/routes/`) take provider
interfaces that run PowerShell workers, and nothing implements them. Add the providers under
`portal/bff/src/providers/`, each built on `runFeatureWorker` (T-0815): translate the route's
typed call into the worker's job envelope (tenant id, action, inputs, actor, and the tenant's `credential` block from the T-0822 credential rows for T-0826's `Connect-WorkerTenant`), run the matching
`portal/workers/*.ps1` entrypoint, and map its JSON back to the provider's return type. Mount
the routes in `app.ts` with the shared repositories, `ctx.caller`, the portal-access
authorizer, and the audit sink from the T-0817 core.

## Acceptance

- [x] Every EPIC-011, EPIC-012, EPIC-013 route module is mounted with a worker-backed provider.
- [x] A test per provider runs it against a fake worker runner and checks the envelope sent and the result mapping.
- [x] An app-level test reaches at least one read and one write route per epic through the server.
- [x] No file outside `scope` is modified.

## Resolution

Landed in three commits, one per epic.

- **EPIC-011** (`adapters/users.ts`): user list, create, lifecycle action, and bulk patch
  providers, and BEC check and remediation, on the T-0007 envelope workers
  (`createEnvelopeWorker`). Stores wrap the db BEC, user template, and offboarding repositories.
  Offboarding runs in the background: the requested re-run step, then every pending step, with
  outcomes written back per step. BEC inbox-rule removal runs once per rule in the finding.
- **EPIC-012** (`adapters/mfa.ts`): MFA report, reset, TAP, push, and default-method providers;
  auth methods policy and registration campaign providers, whose workers gained an
  `action: "get"` read. Migration 0079 creates `tap_records` in the shared database.
- **EPIC-013** (`adapters/roles.ts`): role and PIM assignment lists, PIM request submission
  (new `new-pim-request.ps1` entrypoint for the existing T-0245 worker), live PIM settings read
  and apply, JIT grant/revoke/extend, and the JIT template in-use check.
- `asArray` normalises list output that `ConvertTo-Json` unrolled (one item arrives as an object,
  none as no output).
- Scope additions (fixes found while wiring):
  - Users create dropped each created user's generated one-time password; it is now returned in
    the response only, never stored or audited.
  - The auth methods policy, registration campaign, and PIM role settings reads reported
    all-disabled/default state when Graph failed. They now throw, so admins never see or apply
    against fabricated state.
  - JIT extend ignored the requested hours (always 4) and used a duration counted from now; it now
    takes the hours and the exact new end (`afterDateTime`).
  - Job readers passed ISO timestamps through `[string]` after `ConvertFrom-Json` had made them
    `DateTime`, giving local-format dates (JIT `newEndsAt`, TAP `startTime`, which then shifted by
    the host's UTC offset). Both are kept in UTC ISO form.
  - The PIM settings apply route read live tenant settings before checking permission.
  - db: exported the identity repositories and added `createOffboardingSteps`.
- Providers live in `adapters/` alongside the earlier mount tickets rather than `providers/`.
- Follow-up filed: T-0831 (PIM request approval is not connected to Entra; app-only
  `SelfActivate` needs live verification).
