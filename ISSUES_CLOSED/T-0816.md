# T-0816 — Align route permission strings with the EPIC-038 taxonomy

## Report

EPIC-038 SPEC §11 item 2 fixes the permission taxonomy as `{Area}.{Resource}.{Action}`, and the
T-0741 base roles grant by pattern: `readonly` includes `*.Read`, `editor` `*.Read` and
`*.ReadWrite`, `admin`/`superadmin` `*`. `matchesAccessPattern` is case-sensitive. The feature
routes instead check about 36 ad-hoc lowercase strings — `intune.read`, `intune.write`,
`intune.templates`, `ca.deploy`, `groups.templates`, `drift.triage`, `devices.keys`, … — so once
real authorization is wired (T-0817), only `admin` and `superadmin` could use any feature route;
`readonly` and `editor` would be refused everywhere.

Rename every route permission constant to the taxonomy with `Read` / `ReadWrite` actions (e.g.
`Intune.Policy.Read`, `Intune.Policy.ReadWrite`, `Intune.Template.ReadWrite`,
`ConditionalAccess.Template.ReadWrite`), keeping sensitive reads distinct where the SPEC asks
(e.g. `Device.Keys.Read` for BitLocker/LAPS), and register each endpoint's permission in
`PermissionRegistry`. Add a test that every registered permission is granted to `editor` or
`readonly` by the matching action, except the documented admin-only areas.

## Acceptance

- [x] Every route permission matches `{Area}.{Resource}.{Read|ReadWrite}` (or a documented admin-only permission).
- [x] `readonly` is granted every `.Read` route permission and `editor` every `.ReadWrite` one via `testPortalAccess`.
- [x] Existing permission-registry entries carry the new permissions. Registering every endpoint moved to T-0817, where the completeness test sees the real mounted route list.
- [x] Tests fail without the rename.
- [x] No file outside `scope` is modified, except `portal/bff/src/errors.test.ts`, whose T-0813 test used an old permission literal.

## Resolution

Old → new mapping (60 values in 101 route files):

- Read/ReadWrite by area: `Tenant.{Administration,Alert,Baselines,ConditionalAccess,Drift,Licensing,Reports,ReportTemplate,Standards}`,
  `Identity.{User,Group,GroupTemplate,Mfa,AuthMethodsPolicy,Role,Pim,Jit}`,
  `Endpoint.{Device,Intune,IntuneTemplate}`, `Security.Defender`, `Portal.Dashboard`,
  `CIPP.{Scheduler,Scripts}`, `Remediation.Plan.Read`.
- Admin-only by default (not Read/ReadWrite): `Remediation.Plan` (plan and verify), `Remediation.Apply`
  (also former `drift.remediate`), `Endpoint.DeviceKeys.Reveal` (BitLocker/LAPS), `CIPP.Scripts.Execute`,
  `CIPP.Admin.TenantCredentials`.
- Unchanged: the EPIC-001 run permissions (`runs.*`, `admin`), checked through `rbac/roles.ts`; T-0817
  reconciles the two role systems.

`permissions.test.ts` scans the route sources and fails on any permission outside the taxonomy.
Web UI copy still names `mfa.policy` in two auth-methods tooltips (T-0752 owns permission display).
