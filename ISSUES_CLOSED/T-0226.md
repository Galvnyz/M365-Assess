# T-0226 — Registration campaign toggle with groups and exclusions

## Report

EPIC-012 SPEC.md §3.4 and §4.4 (US-7): the registration campaign is a toggle plus configuration
(included/excluded groups, snooze days) with a summary of eligible users; state is read back from
Graph. §11.3 resolves the inclusion model to **groups plus explicit exclusions** (not
all-users-with-exclusions).

Add `GET`/`PUT /v1/tenants/{id}/registration-campaign` to `registration-campaign.ts`, and the
`Set-RegistrationCampaign.ps1` worker job plus `set-registration-campaign.ps1` entrypoint that
applies the toggle and configuration through the EPIC-006 apply/audit path (T-0108). `GET`
returns Graph state plus an eligible-user count derived from the include/exclude groups; extend
`portal.v1.yaml`.

## Acceptance

- [x] `PUT` starts/stops the campaign with include and exclude groups and snooze days.
- [x] `GET` reflects Graph state and the eligible-user count for the configured groups.
- [x] Starting a campaign is audited and honors the gate.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
