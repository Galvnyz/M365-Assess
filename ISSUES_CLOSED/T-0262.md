# T-0262 — Group CRUD worker and API with dynamic-rule validation

## Report

EPIC-014 SPEC.md §4.1 requires create/edit/delete with a **plan preview**, and that dynamic
membership rules are **validated before apply**; §6 fixes `POST /v1/tenants/{id}/groups` and
`PATCH`/`DELETE /v1/tenants/{id}/groups/{groupId}`. §8 mandates every write route through
EPIC-006: plan preview, confirmation, and a per-change `AuditEvent`. §11.4 resolves the dynamic
rule editor to a **raw rule string with validation** rather than a guided builder, and §11.1
scopes v1 to M365, security, and distribution types.

Deliver `Set-Group.ps1` (a handler covering the create/edit/delete/convert operations, with v1
limited to the §11.1 types) and `set-group.ps1` (entrypoint), plus `groups-crud.ts` behind the
gated-write seam of EPIC-006's apply API (T-0108) from the RBAC seam (T-0013). Creation and
edits produce a JSON plan/diff returned to the caller before apply; the dynamic rule is
validated (non-empty membership rule, valid property/operator expressions) and Graph errors are
surfaced rather than swallowed (§9). Delete requires explicit confirmation naming the group and
records the before/after state.

## Acceptance

- [x] Create, edit, and delete work with a returned plan preview; delete requires a naming confirmation.
- [x] Invalid dynamic rules are rejected before apply with a structured error.
- [x] Each write produces a per-change audit record through the EPIC-006 path.
- [x] Tests cover the route and handler and fail without them.
- [x] No file outside `scope` is modified.
