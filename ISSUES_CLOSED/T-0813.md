# T-0813 — Define ErrorCodes.forbidden and ErrorCodes.notFound

## Report

`ErrorCodes` in `portal/bff/src/errors.ts` defines only `routeNotFound`, `validationFailed`,
and `internalError`, yet 21 route files reference `ErrorCodes.forbidden` (22 uses) and
`ErrorCodes.notFound` (14 uses) — CA, groups, PIM, JIT, roles, and the T-0301/T-0302 Intune
routes. Those evaluate to `undefined`, so the 403/404 responses they raise carry
`code: undefined`: clients cannot branch on the error, and each use is a `tsc` error.

Add the two keys centrally instead of editing 21 files:

- `forbidden: "auth.forbidden"` — the same value as `RbacErrorCodes.forbidden`, so every 403
  carries one code whichever constant raised it.
- `notFound: "resource.not_found"` — a missing resource, kept distinct from `routeNotFound`
  (`request.not_found`, an unknown route).

## Acceptance

- [x] `ErrorCodes.forbidden` equals `RbacErrorCodes.forbidden`; `ErrorCodes.notFound` is distinct from `routeNotFound`.
- [x] `tsc` no longer reports `ErrorCodes.forbidden` / `ErrorCodes.notFound` as missing.
- [x] A test asserts both codes and that a route 403/404 response carries a defined `code`; it fails without the change.
- [x] No file outside `scope` is modified.
