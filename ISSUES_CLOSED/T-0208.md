# T-0208 — User templates and per-tenant offboarding defaults

## Report

EPIC-011 SPEC.md §3.5 and §5 (US-7): **User Templates** define default properties (usage
location, licenses, groups) and **offboarding defaults** applied at creation and offboarding.
§11.5 resolves mailbox access defaults to **per-tenant offboarding defaults (from the template),
with the wizard allowed to override per run.**

Add the `UserTemplate` entity (`id`, `name`, `properties`, `licenses[]`, `groups[]`,
`offboardingDefaults`) via the next forward-only migration and a
`user-templates-repository.ts`; expose `GET`/`POST`/`PATCH`/`DELETE` `/v1/user-templates` in
`user-templates.ts`, and extend `portal.v1.yaml`. The template's creation defaults are consumed
by the create path (T-0202) and its offboarding defaults by the plan builder (T-0205); a
template never writes to a tenant on its own.

## Acceptance

- [x] Templates CRUD persists properties, licenses, groups, and offboarding defaults and round-trips them.
- [x] A creation run with a template seeds usage location, licenses, and groups; a run without one uses documented fallbacks.
- [x] Offboarding defaults resolve into the plan's mailbox access mode unless the wizard overrides it.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
