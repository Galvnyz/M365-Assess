# T-0246 — JIT admin grants: advisory and bounded

## Report

EPIC-013 SPEC.md §3.4 and §4.4 (US-5): grant a user an eligible/active admin role for a bounded
window from a template; row actions `Grant`, `Revoke`, `Extend`. §5 defines `JitGrant` (`id`,
`tenantId`, `userId`, `roleId`, `startsAt`, `endsAt`, `state`, `createdBy`) as **expiring**.
§11.2 resolves JIT as **advisory first — it grants bounded eligible/active roles and does not
remove permanent assignments.**

Add the `JitGrant` entity via the next forward-only migration and a `jit-repository.ts`, then
`POST /v1/tenants/{id}/jit-grants` and `POST /v1/jit-grants/{id}/revoke` in `jit-grants.ts`, and
the `New-JitGrant.ps1` worker job plus `new-jit-grant.ps1` entrypoint. Grants are bounded and
audited through the EPIC-006 apply/audit path (T-0108); no path removes an existing permanent
assignment. Extend `portal.v1.yaml`.

## Acceptance

- [x] A grant creates a bounded, audited eligible/active assignment with `startsAt`/`endsAt`.
- [x] Revoke ends the grant early; extend adjusts the window within the role's maximum duration.
- [x] JIT never removes or mutates an unrelated permanent assignment.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
