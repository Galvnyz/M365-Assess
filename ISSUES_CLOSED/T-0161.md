# T-0161 — Drift template (one per tenant) with clone-to-seed

## Report

EPIC-009 SPEC.md §5 defines `DriftTemplate` as a `StandardTemplate` with `kind: drift`.
Resolved §11.1 adopts **enforced 1:1 per tenant, with clone to seed**, matching CIPP's single
desired-state template per tenant (US-1). §9 rates "scope explosion" a risk mitigated by drift
being **opt-in per tenant**.

Deliver the `DriftTemplate` contract type, forward-only migration (`0009`), and repository
enforcement of the one-per-tenant constraint. A clone operation seeds a new tenant's template from
an existing one (including its standards and per-setting auto-remediation flags). No detection or
UI here.

## Acceptance

- [x] A tenant has at most one drift template; a second create is rejected or resolves to the existing row.
- [x] Clone-to-seed copies the source template's standards and settings into a new tenant's template.
- [x] Drift is opt-in: a tenant without a template produces no drift state.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
