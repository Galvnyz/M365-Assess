# T-0127 — Custom script CRUD, versions, and dry-run/run API

## Report

EPIC-007 SPEC.md §6 defines `GET`/`POST`/`PATCH`/`DELETE /v1/scripts`,
`GET`/`POST /v1/scripts/{id}/versions`, and `POST /v1/scripts/{id}/run` (dry-run / run, gated).
§4.3 step 2: a **dry run** executes against a chosen tenant and shows output without side
effects. §11.3 resolves to **support an explicit dry-run contract scripts opt into**. §7 makes
`scripts.run` higher privilege because it is arbitrary code.

Deliver:

- Route handlers over T-0125's repository: CRUD, version list/create, and run.
- The `run` endpoint accepts a `dryRun` flag, calls T-0126's sandbox, and rejects a real run when
  the script does not declare the dry-run contract or the caller lacks `scripts.run`.
- OpenAPI updated; tests for CRUD/versioning, dry-run opt-in, and privilege gating.

## Acceptance

- [x] CRUD and version creation work; saving always appends a version.
- [x] A dry run executes and returns output without persisting side effects.
- [x] A non-dry run by a caller without `scripts.run` is rejected.
- [x] A script without the dry-run contract cannot be dry-run silently as a real run.
- [x] No file outside `scope` is modified.
