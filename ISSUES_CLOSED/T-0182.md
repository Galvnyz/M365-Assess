# T-0182 — Baseline CRUD, assignment, and save gate

## Report

EPIC-010 SPEC.md §6 fixes baseline CRUD (`GET`/`POST`/`PATCH`/`DELETE /v1/baselines`) and
`POST /v1/baselines/{id}/assign` (US-1, US-2). §4.1 step 3: **save is blocked until a name, an
assignment, and at least one staged standard exist**; §10 repeats this as an acceptance
criterion. §7 requires `baselines.read` for reads and `baselines.write` for mutations, tenant-scoped
via `UserScope` (prose: EPIC-001 T-0013 RBAC seam).

Deliver the route handlers and `baseline-validate.ts`. Assignment reuses the tenants/groups model
owned by EPIC-002 (prose cross-ref), not a re-implementation.

## Acceptance

- [x] The four CRUD endpoints and `/assign` are implemented and match the OpenAPI document.
- [x] A save without a name, an assignment, or a staged standard is rejected with a structured error.
- [x] Non-`baselines.write` callers receive a structured error; assignment validates target scope.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
