# T-0221 — MFA report read API and aggregation

## Report

EPIC-012 SPEC.md §3.1 and §4.1 (US-1) require `GET /v1/tenants/{id}/mfa-report` to aggregate
users plus `authenticationMethods` into registration, method, and phishing-resistant state, with
drill-through to a user's methods. §9 forbids inferring phishing-resistance from anything but
Graph — use the classifier from T-0227. §5 says no user method data is mirrored beyond the
report query.

Add the BFF route to `mfa.ts`, and the read-only `Get-MfaReport.ps1` worker job plus
`get-mfa-report.ps1` entrypoint that reads the job envelope (T-0007), runs through the EPIC-001
worker/queue path (T-0010) using child-process credential materialization (T-0011), and returns
per-user methods, default method, phishing-resistant flag, last auth, and state, plus the KPI
aggregates. Extend `portal.v1.yaml`. Depends on EPIC-011's user read (T-0201) for user context.

## Acceptance

- [x] `GET /v1/tenants/{id}/mfa-report` returns all users with methods, default method, and phishing-resistant state.
- [x] The KPI aggregates (total, registered, not-registered, phishing-resistant, per-method) reconcile with the rows.
- [x] The worker is read-only and the BFF route holds no M365 SDK call.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
