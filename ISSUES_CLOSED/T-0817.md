# T-0817 — Composition root core: app, authorization, and self-contained routes

## Report

`index.ts` calls `buildServer()` with no routes. A second scope review found that almost none of
the ~40 store/queue/port interfaces the EPIC-001–010 routes take (`RunStore`, `TenantStore`,
`DriftStore`, `BaselinesStore`, …) has an implementation: the `@m365-assess/db` repositories
exist but expose different method shapes, and the BFF does not depend on that package. Each area
therefore needs adapters, carried by T-0821 to T-0825. This ticket builds what they all plug into:

1. `app.ts` — `createApp(config)` opens one SQLite database under `storagePath`, builds the
   shared authorizer, audit sink, and authenticators, and returns the route list for
   `buildServer`. Areas contribute routes through one list so later tickets only add entries.
2. **Authorization** — one portal-access authorizer (T-0743 `testPortalAccess`) exposed in the
   shapes the route modules take (`(caller, permission) => void` and `(ctx, permission) =>
   boolean`), passed to every mounted route so none falls back to its permissive default. It
   reconciles the EPIC-001 role system: `admin`/`operator` map to the `admin`/`readonly` base
   roles and the run permissions (`runs.*`, `admin`) to taxonomy names.
3. **Identity** — API-client authentication (T-0748) plus an explicit, opt-in local dev identity
   (refused when `NODE_ENV=production`) until EPIC-038 delivers portal-user token validation.
4. Mount the routes that need no new storage: health, the baselines catalog, and the template
   CRUD routes backed by existing BFF SQLite repositories (CA, Intune, group templates).
5. `permissions.test.ts` checks the app's real route list, and `PermissionRegistry` lists every
   mounted endpoint.

## Acceptance

- [x] `index.ts` serves the app's routes; the mounted set is health, baselines catalog, and CA/Intune/group template CRUD.
- [x] Every mounted route receives the portal-access authorizer; a `readonly` caller is refused a write route and allowed a read route.
- [x] EPIC-001 roles and run permissions resolve through the same authorizer as base roles.
- [x] The dev identity only activates when explicitly configured and never in production.
- [x] The permission completeness test runs against the app's real route list, and `PermissionRegistry` lists every mounted endpoint.
- [x] Tests fail without the composition root.
- [x] No file outside `scope` is modified.

## Resolution

- `createApp` serves health (Public), the baselines catalog, and CA/Intune/group template CRUD on
  one SQLite database (`<storagePath>/portal.db`).
- `canAccess`/`authorizeCaller`/`authorizeContext` wrap `testPortalAccess`; EPIC-001 `admin`/`operator`
  map to the `admin`/`readonly` base roles, and `runs.*`/`admin` to `Tenant.Runs.{Read,ReadWrite}` and
  `CIPP.Admin.Diagnostics`. Anonymous callers get 401 from either shape.
- Identity: only the opt-in dev identity (`M365_BFF_DEV_IDENTITY=admin|operator`, refused in production)
  is wired. API-client authentication (T-0748) needs an Entra token validator (`validateToken`) that
  does not exist yet, so it is not mounted; with no identity configured, protected routes answer 401.
- Noted, not changed: the T-0305 Intune template routes answer 403 with `request.forbidden` rather than
  the shared `auth.forbidden`.
