# T-0202 — User create and CSV bulk create with schema and validation

## Report

EPIC-011 SPEC.md §4.1 (US-2): single create is *form → plan → apply* (gated); bulk create is
*CSV upload → validate → plan → apply per row* with **partial failures reported per row**. §11.4
resolves the open question by requiring the CSV column schema and validation rules to be
defined here: build `portal/bff/src/domain/users/csv.ts` with the accepted columns (UPN, display
name, given/surname, usage location, licenses, groups, and per-tenant defaults), required-field
and format validation, duplicate detection against the tenant, and a row-level result model.

The BFF adds `POST /v1/tenants/{id}/users` (single and bulk modes) to `users.ts`; the
`New-TenantUser.ps1` worker job plus `new-tenant-user.ps1` entrypoint apply each planned create
through the EPIC-006 gated executor (T-0107) so every write is confirmed, captured
before/after, and audited. Unknown licenses or a missing usage location are validation failures,
not partial applies.

## Acceptance

- [x] `csv.ts` defines the column schema and rejects missing UPN/display name, bad format, and duplicates per row.
- [x] Single and bulk create both produce per-row results; a partial failure does not abort successful rows.
- [x] Every create routes through the EPIC-006 gate/executor and writes an audit record.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
