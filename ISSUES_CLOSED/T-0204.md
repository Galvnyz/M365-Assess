# T-0204 — User lifecycle actions API

## Report

EPIC-011 SPEC.md §3.1 and §4.3 (US-4): reset password, require password change, revoke sessions,
disable/enable, and restore a deleted user are each a **gated write** routed through EPIC-006,
confirmed and audited. Add
`POST /v1/tenants/{id}/users/{userId}/actions/{action}` to `users.ts` covering the lifecycle
action set, and implement the `Invoke-UserAction.ps1` worker job plus `invoke-user-action.ps1`
entrypoint.

Each action uses the EPIC-006 gated executor (T-0107): destructive or session-breaking actions
(revoke sessions, disable, delete-restore) require confirmation, capture before/after, and write
an `AuditEvent`. Restore is available only for a soft-deleted user and must surface the restored
state. Unknown action names are rejected with a structured error, never passed through.

## Acceptance

- [x] Each lifecycle action in the §4.3 set is dispatched by the route and executed by the worker.
- [x] Reset password returns any one-time value without persisting or logging it.
- [x] Every action is confirmed where destructive and writes before/after plus an `AuditEvent`.
- [x] An unknown action returns a structured 4xx, not a silent no-op.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
