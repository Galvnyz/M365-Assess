# T-0207 — BEC check worker and per-finding remediation

## Report

EPIC-011 SPEC.md §3.2 and §4.5 (US-6): the BEC tab runs CIPP's 11-check review (mailbox rules,
recently added users, new applications, mailbox permission changes, sent messages, MFA devices,
password changes, trusted & blocked senders, Intune devices, sign-in locations, sharing links);
findings are presented with **per-finding remediate actions** (remove rule, revoke session,
reset MFA, remove permission) routed through EPIC-006. §11.3 resolves BEC remediation as
**per-finding manual approval only — the portal never auto-remediates BEC.**

Add `POST /v1/tenants/{id}/users/{userId}/bec-check` and the per-finding remediate route to
`bec.ts`; implement the read-only `Invoke-BecCheck.ps1` worker job plus
`invoke-bec-check.ps1` entrypoint returning the 11 checks, and persist `BecFinding` (`id`,
`tenantId`, `userId`, `check`, `detail`, `state`) via `bec-repository.ts`. Each finding carries
its evidence; remediation calls the EPIC-006 gated executor (T-0107) one finding at a time after
explicit approval. Extend `portal.v1.yaml`.

## Acceptance

- [x] The check returns all 11 checks with per-check detail and a finding state.
- [x] Each finding exposes a remediate action; applying it is individually confirmed and audited.
- [x] No automatic/bulk BEC remediation path exists; evidence is always shown before approval.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
