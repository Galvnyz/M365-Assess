# T-0819 — Mount the Groups and Conditional Access routes with worker-backed providers

## Report

The route modules for EPIC-014, EPIC-015 (groups and Conditional Access: `groups-*.ts group-templates*.ts ca-*.ts` under `portal/bff/src/routes/`) take provider
interfaces that run PowerShell workers, and nothing implements them. Add the providers under
`portal/bff/src/providers/`, each built on `runFeatureWorker` (T-0815): translate the route's
typed call into the worker's job envelope (tenant id, action, inputs, actor, and the tenant's `credential` block from the T-0822 credential rows for T-0826's `Connect-WorkerTenant`), run the matching
`portal/workers/*.ps1` entrypoint, and map its JSON back to the provider's return type. Mount
the routes in `app.ts` with the shared repositories, `ctx.caller`, the portal-access
authorizer, and the audit sink from the T-0817 core.

## Acceptance

- [x] Every EPIC-014, EPIC-015 route module is mounted with a worker-backed provider.
- [x] A test per provider runs it against a fake worker runner and checks the envelope sent and the result mapping.
- [x] An app-level test reaches at least one read and one write route per epic through the server.
- [x] No file outside `scope` is modified.

## Resolution

- `adapters/groups.ts` implements the group list, usage, CRUD, GAL/delivery, bulk membership,
  and template deploy providers; `adapters/conditional-access.ts` implements the CA policy list,
  CRUD, coverage, report-only, named location, and template deploy providers. Both build on
  `createTenantWorker` (moved from the Intune adapter into `adapters/workers.ts`), which sends
  the tenant's credential block and maps worker failures to 502s.
- A group template deploy runs the worker once per target tenant, sequentially. A failing target
  (no credential, blocked name conflict, Graph error) is reported as a failed deployment for that
  tenant instead of failing the others.
- These route modules return worker audit events in their responses rather than taking an audit
  sink, so `recordResponseAudit` in `app.ts` records `auditEvent`/`auditEvents` from write
  responses with the signed-in actor.
- `resolveCaller` now adds `userId` (from the portal user's `id`), so template deploys are
  stamped with the real user instead of "system".
- CA change history is served from the portal's `audit_events` rows. The directory-audit half of
  SPEC §4.4 needs a worker that does not exist; filed as T-0830.
- Worker fix (scope addition): the named-location worker always passed `isTrusted`,
  `includeUnknownCountriesAndRegions`, and `countryLookupMethod`, so an edit that left them out
  reset them to false/`clientIpAddress`. They are now forwarded only when the job sets them, with
  Pester tests.
- Registry entries for all 22 group and CA endpoints were added to `rbac/permissions.ts`
  (scope addition), in mount order.
- Providers live in `adapters/` alongside the T-0820/T-0822 adapters rather than `providers/`.
