# T-0822 — Mount the Tenants and onboarding routes on real storage

## Report

The EPIC-002 route modules (tenants.ts, tenant-groups.ts, tenant-variables.ts, credentials.ts, gdap.ts, onboard.ts, test-connection.ts) take interfaces with no implementation: `TenantStore`, `TenantGroupStore`, `TenantVariableStore`, `CredentialStoreRow`/`CredentialStore`, `GdapRelationshipStore`, and the worker-backed `OnboardRunner`, `TestConnectionRunner`, and `GdapSyncRunner` (via `runFeatureWorker`, T-0815). The
`@m365-assess/db` repositories hold the data but expose different method shapes, and the BFF does
not yet depend on that package.

Add `@m365-assess/db` as a BFF dependency if it is not already present, write adapters under
`portal/bff/src/adapters/` that implement each interface on top of the db repositories (or the BFF's
own repositories where the entity lives there), and mount the routes in `app.ts` with the T-0817
authorizer, caller resolution, and audit sink. Adapters translate shapes only — no domain logic
(ADR-0014 thin BFF).

## Acceptance

- [x] Every EPIC-002 route module is mounted on adapters over persistent storage (no in-memory fakes).
- [x] Each adapter has a test against a real in-memory SQLite database.
- [x] An app-level test reaches at least one read and one write route per epic through the server with the authorizer applied.
- [x] No file outside `scope` is modified.

## Resolution

- `adapters/tenants.ts` implements the tenant, group, variable, credential-row, and GDAP stores on
  `@m365-assess/db`'s `SqliteRepository` (method renames only; shapes already matched).
- `adapters/workers.ts`: `credentialBlock`/`toCredentialBlock` (credential reference plus non-secret row
  for T-0826), `createWorkerRunner`, and the test-connection, onboarding, and GDAP-sync runners.
- New entrypoints `test-tenant-connection.ps1`, `onboard-tenant.ps1`, `sync-gdap-tenants.ps1`
  (scope addition: the worker functions existed but had no job-file entrypoint).
- `createApp` runs the db migrations once on the shared connection and mounts all seven EPIC-002
  route modules; registry entries are projected from each module's OpenAPI fragment
  (`registryEntriesFromOpenApi`). GDAP sync mounts only when `M365_BFF_GDAP_PARTNER_TENANT_ID` is set.
- Config gains `workersDir` and `gdapPartnerTenantId`; the BFF now depends on `@m365-assess/db` and
  `better-sqlite3`, and the workspace order builds `db` before `bff`.
- Exceptions to "no in-memory fakes": credential secret material stays in memory until T-0827.
  SKU-filtered tenant groups match nothing until a license inventory exists (T-0828).
- Fixed on the way: `tenant-groups.write` escaped the T-0816 rename (its hyphen hid it from the guard);
  it is now `Tenant.Administration.ReadWrite` and the guard recognises hyphenated names.
