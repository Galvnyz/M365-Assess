# T-0825 — Mount the Standards, drift, and baselines routes on real storage

## Report

The EPIC-008, EPIC-009, EPIC-010 route modules (standards-*.ts, drift*.ts, baselines*.ts (the catalog route is mounted by T-0817)) take interfaces with no implementation: the standards, drift, and baseline stores, `DriftRefresh`, the drift remediation ports, and the standards run queue. The
`@m365-assess/db` repositories hold the data but expose different method shapes, and the BFF does
not yet depend on that package.

Add `@m365-assess/db` as a BFF dependency if it is not already present, write adapters under
`portal/bff/src/adapters/` that implement each interface on top of the db repositories (or the BFF's
own repositories where the entity lives there), and mount the routes in `app.ts` with the T-0817
authorizer, caller resolution, and audit sink. Adapters translate shapes only — no domain logic
(ADR-0014 thin BFF).

## Acceptance

- [x] Every EPIC-008, EPIC-009, EPIC-010 route module is mounted on adapters over persistent storage (no in-memory fakes).
- [x] Each adapter has a test against a real in-memory SQLite database.
- [x] An app-level test reaches at least one read and one write route per epic through the server with the authorizer applied.
- [x] No file outside `scope` is modified. (Scope additions below, as in T-0824.)

## Resolution

- Standards templates, assignments, and the catalog persist through the db standards repository;
  a template's schedule is a row in the schedule store. The standards catalog (EPIC-008) was
  unmounted too and is mounted here; the baselines catalog was already mounted by T-0817.
- Drift deviations and triage persist through the db drift repository. Baselines, stages,
  assignments, rollouts, history, and trend persist through the db baselines repository; the fleet
  view counts deviations from the drift repository.
- Not wired, refused with 501 and filed as T-0841: standards run-now and drift refresh (no worker
  entrypoints), and denials that delete. The deny routes write `denied`/`deletePending` before they
  queue the delete, so `refuseDriftDeletion` refuses single deny and bulk `deny-delete` after
  authorization but before the route writes anything. Bulk accept and deny-remediate only record
  triage state and work.
- A tenant-scoped catalog request (`?tenantId=`) is refused with 501 until tenant licence inventory
  exists (T-0828); without a resolver the route would answer 500.
- Scope additions:
  - `portal/db`: migration `0081_standard_compare.sql` (the StandardCompare store the alignment and
    compare views read; no table existed); `updateStandardTemplate`, `upsertCompare`, `listCompare`;
    deviation lookup and triage by id, cross-tenant listing, and state counts; rollouts across
    baselines, and history and trend reads and writes on the 0069 tables. The standards, drift,
    and baselines repositories are now exported, with views that rename the check reference for
    the BFF guard.
  - `portal/bff/src/rbac/permissions.ts`: registry entries for the new endpoints. The advance,
    alignment, and migrate fragments name the baseline parameter `{id}`, so they are registered by
    their route path constants.
