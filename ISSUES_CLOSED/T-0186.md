# T-0186 — Manual stage advance

## Report

EPIC-010 SPEC.md §3.4 shares the **Move to next stage** triage dialog (`advanceStage`) with
EPIC-008/009, and §6 fixes `POST /v1/baselines/{id}/stages/{order}/advance` (US-3). §4.2 step 2
lets the operator move a tenant once it satisfies the stage conditions. Resolved §11.2 adopts
**manual advancement first**, with an optional auto-advance policy deferred to a later ticket.
§7 requires `baselines.advance`.

Deliver the advance handler: it advances only a tenant currently marked eligible (T-0185),
records the move as a history event, and rejects an ineligible advance with a structured error.
Writes are audited.

## Acceptance

- [x] A tenant advances one stage only when its current stage conditions are met.
- [x] An ineligible advance is rejected with a structured error and no state change.
- [x] The advance is audited and a history event is recorded; non-`baselines.advance` callers are refused.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
