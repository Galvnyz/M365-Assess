# T-0230 — Authentication methods policy and registration campaign UI

## Report

EPIC-012 SPEC.md §3.3 (US-6): the **Authentication Methods** page offers preset selection with
per-method enable/target configuration and a **plan preview** before apply. §3.4 (US-7): the
**Registration Campaign** toggle plus included/excluded groups, snooze days, and a summary of
eligible users.

Build the route, `AuthMethodsPolicyEditor` (preset picker, current-vs-proposed diff from the
T-0225 preview, apply confirmation), `RegistrationCampaignPanel` (toggle, group pickers, snooze
days, eligible-user summary from T-0226), and a typed `authMethodsApi.ts`. Apply is gated by
`mfa.policy` (rendered disabled with a reason when absent). Use report theme tokens only.

## Acceptance

- [x] The editor shows the current-vs-proposed diff from the preview endpoint before applying.
- [x] Apply is enabled only when the caller holds `mfa.policy`; otherwise it is disabled with a reason.
- [x] The campaign panel toggles and reflects Graph state plus the eligible-user count.
- [x] Only report theme tokens/classes are used; no colour literals.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
