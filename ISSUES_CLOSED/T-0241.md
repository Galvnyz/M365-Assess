# T-0241 — Directory role assignments read API

## Report

EPIC-013 SPEC.md §3.1 and §4.1 (US-1): the **Roles & Assignments** view reads role assignments
from Graph, aggregates by principal and role, and surfaces **permanent-vs-eligible** clearly
(permanent admin assignments are a common finding). §6 exposes
`GET /v1/tenants/{id}/role-assignments`.

Add the BFF route to `roles.ts` and the read-only `Get-RoleAssignments.ps1` worker job plus
`get-role-assignments.ps1` entrypoint that reads the job envelope (T-0007), runs through the
EPIC-001 worker/queue path (T-0010) using child-process credential materialization (T-0011), and
returns role, principal, type (permanent/eligible/active), scope, start, end, and status with
filters and cursor pagination. Extend `portal.v1.yaml`. Depends on EPIC-002 for tenant/credential
records (not yet authored) and on the EPIC-038 RBAC model for who may read (not yet authored).

## Acceptance

- [x] `GET /v1/tenants/{id}/role-assignments` returns assignments with the §3.1 columns and filters.
- [x] Permanent assignments are distinguishable from eligible/active ones.
- [x] The worker is read-only and the BFF route holds no M365 SDK call.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
