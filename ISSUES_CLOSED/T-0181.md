# T-0181 — Baseline and BaselineStage entities and repository

## Report

EPIC-010 SPEC.md §5 defines `Baseline` (`id`, `name`, `stages[]`, `logic`, `alerting`, `enabled`)
and `BaselineStage` (`baselineId`, `order`, `conditions[]`, `action`) as **ordered** stages using
`logic: 'and'`. Resolved §11.1 defers broad baseline rollout until the shared standards/conditions
model (EPIC-008 T-0142) lands, so this ticket builds on that model rather than a parallel one.
§9 rates "rollout complexity" a risk mitigated by `and`-only logic for v1.

Deliver the contract types, forward-only migration (`0011`), and repository methods to create,
read, update, and order stages and conditions. No route or UI here.

## Acceptance

- [x] `Baseline` and `BaselineStage` persist with ordered stages and `logic: 'and'`.
- [x] Migration `0011` applies after the current head, is re-runnable, and advances `SchemaVersion`.
- [x] The repository enforces unique, contiguous stage ordering per baseline.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
