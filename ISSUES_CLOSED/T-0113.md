# T-0113 — Apply confirmation dialog and remediation history view

## Report

EPIC-006 SPEC.md §3.3: an `ActionDialog` lists the selected checkIds and target tenants, with a
second confirmation for batch applies showing the count. Fields: reason (required), `Dry run`
switch (default on). On confirm, results render inline (`.status-badge` per action) with a
**View audit** link. SPEC.md §3.4: nav *Tenant Administration → Remediation → History*, an
append-only table with timestamp, actor, tenant, check ID, command, before → after, result, and
correlation ID; export to SIEM is EPIC-041.

Build `ApplyActionDialog` (calling `POST /plans/{planId}/apply` with a generated
`Idempotency-Key` and the dialog's `dryRun` value) and the `history/page.tsx` +
`RemediationHistoryTable` reading `GET /v1/remediation/history`. Reuse the ActionDialog/status
badge components.

## Acceptance

- [x] Confirmation lists the selected checkIds/tenants; a batch apply shows a second count confirmation.
- [x] `Dry run` defaults on; `reason` is required before confirm.
- [x] Results render inline per action and link to the audit trail.
- [x] History renders the append-only columns from the history endpoint.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
