# T-0815 — Feature worker runner on the job supervisor

## Report

The route providers for EPIC-011 through EPIC-018 (e.g. `IntuneTemplateDeployProvider`,
`ReusableSettingsProvider`, `AssignmentFilterProvider`) each need to run a PowerShell worker
entrypoint with a JSON job envelope and read its JSON result. `jobs/supervisor.ts` supervises a
worker process (timeout, cancellation, progress), but `buildWorkerArgs` is hard-wired to
`run-tenant.ps1`'s arguments (`-ContextFile`, `-OutputFolder`, `-JobId`, …), and the result is
read from `result.json`, whereas feature entrypoints take one `-JobFile <path>` and print JSON on
stdout. Two entrypoints (`get-intune-policies.ps1`, `set-intune-policy.ps1`) take `-JobPath`
instead of the `-JobFile` the other 32 use.

Deliver `jobs/feature-worker.ts`: `runFeatureWorker(entrypoint, job, options)` writes the job
envelope to a private temp file, launches `pwsh -NoProfile -NonInteractive -File <entrypoint>
-JobFile <file>` through the supervisor (add a `buildArgs`/result-reader option rather than a
second spawn path), parses stdout as JSON, maps a non-zero exit or unparsable output to a typed
error carrying the worker's stderr summary, and deletes the job file. Rename the two `-JobPath`
parameters to `-JobFile`.

## Acceptance

- [x] `runFeatureWorker` runs an entrypoint with `-JobFile` via the supervisor and returns its parsed JSON.
- [x] Timeouts, cancellation, non-zero exits, and bad JSON surface as typed errors; the job file is always removed.
- [x] All worker entrypoints take `-JobFile`.
- [x] Tests (with a fake spawn) cover success and each failure mode and fail without the change.
- [x] No file outside `scope` is modified.
