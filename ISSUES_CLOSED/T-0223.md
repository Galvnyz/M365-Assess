# T-0223 — Temporary Access Pass creation (shown once, never stored)

## Report

EPIC-012 SPEC.md §3.2 and §4.2 (US-3): the **TAP** action configures lifetime, one-time-use,
and start time, and **shows the pass once**. §5 defines `TAPRecord` (`id`, `tenantId`, `userId`,
`createdAt`, `createdBy`, `lifetime`, `oneTime`) and states it **never stores the pass value**;
§9 flags TAP leakage as a risk and requires show-once, never persist/log.

Add `POST /v1/tenants/{id}/users/{userId}/tap` to `mfa.ts`, the `New-TemporaryAccessPass.ps1`
worker job plus `new-temporary-access-pass.ps1` entrypoint, and a `tap-repository.ts` that
persists only the non-secret record. The pass value is returned in the response body once,
redacted from logs, and excluded from audit; a test asserts it is absent from storage and audit.

## Acceptance

- [x] Creating a TAP returns the value exactly once and persists a `TAPRecord` without the value.
- [x] Lifetime, one-time-use, and start time are honored and recorded.
- [x] The pass value never appears in the repository, logs, or audit.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
