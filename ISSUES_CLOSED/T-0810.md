# T-0810 — Assignment filters and policy compare pages

## Report

EPIC-016 SPEC.md §3 puts **Assignment Filters** and **Policy compare** under *Intune → Device
Management*. T-0309 delivered `AssignmentFilterTable` and T-0310 delivered `PolicyCompareView`,
but their ticket scopes held no page, so neither is reachable. The T-0303 list pages already
route **Compare** to `/intune/policies/compare?tenantId=<t>&kind=<kind>&left=<policyId>`, which
404s today.

Add the two Next.js pages, following the existing page convention (pages own
`next/navigation`; components stay router-free):

- `/intune/assignment-filters?tenantId=<t>` renders `AssignmentFilterTable` with the tenant and
  the deploy-target tenants from `listDeployTargets()` (T-0307).
- `/intune/policies/compare` reads `tenantId`, `kind`, `left` (and optional `right`), converts
  `left` to the `policy:<kind>:<id>` ref, and renders `PolicyCompareView`. Its `rightOptions`
  are the other policies of the same kind (`fetchIntunePolicies`) plus templates of that
  `policyType` (`listIntuneTemplates`); put that assembly in a pure `buildCompareOptions` helper
  in `intuneApi.ts` so it is unit-tested (web has no `next` installed, so pages are not).

## Acceptance

- [x] Both pages exist; the T-0303 **Compare** action lands on a working compare view.
- [x] Compare options list same-kind policies (excluding the left policy) and same-type templates only.
- [x] `buildCompareOptions` is covered by a test that fails without it.
- [x] No file outside `scope` is modified.
