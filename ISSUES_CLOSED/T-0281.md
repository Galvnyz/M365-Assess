# T-0281 — Conditional Access policy read API

## Report

EPIC-015 SPEC.md §3.1 defines the **Conditional Access Policies** table — Name · State
(on/off/report-only) · Users targeted · Apps · Grant/block controls · Conditions · Modified ·
Modified by — plus filters (state, target, control, condition, modified date). §4.4 needs the
policy set as the basis for coverage and change history, and §6 fixes
`GET /v1/tenants/{id}/ca/policies`. Policies are read live from Graph (EPIC-015 §5); the module
already uses `Policy.Read.All` (§7).

Deliver a read-only worker handler `Get-CaPolicies.ps1` + `get-ca-policies.ps1` entrypoint
(rehydrating the EPIC-001 `RunContext`) and the BFF route behind the RBAC seam (T-0013). The
handler projects each policy into a flat row: state, targeted users/groups/roles, apps,
grant/session controls, conditions, and the directory `modifiedDateTime`/`modifiedBy`. Filtering
and search are applied server-side with cursor pagination. No writes.

## Acceptance

- [x] `GET /v1/tenants/{id}/ca/policies` returns state, targets, controls, conditions, and modification info.
- [x] State/target/control/condition/date filters and search work and are covered by tests.
- [x] The handler is read-only; the T-0015 guard test still passes.
- [x] Tests cover the route and handler and fail without them.
- [x] No file outside `scope` is modified.
