# T-0111 — Finding remediation panel (automated + manual tabs)

## Report

EPIC-006 SPEC.md §3.1: the finding detail drawer (EPIC-004) gains a tabbed remediation block
(`.rem-tab`, as in the module report's Direction-D panel) with an **Automated** tab (desired
state, the exact command in mono font, preconditions as `.status-badge` chips for
license/service/RBAC/allowlist, and a **Copy plan** button) and a **Manual** tab (the registry
`portal.path` as a breadcrumb plus numbered `steps[]`, each a row, with **Copy steps**). An
`undetermined` check shows the empty state: "No remediation defined — triage required."

Build `FindingRemediationPanel` and `ManualSteps` under `portal/web/src/components/remediation/`
and a typed `remediationApi.ts` client for the T-0105 plan/instruction endpoints, following the
report theme and `cipp-ui-patterns.md` tokens. The drawer integration point is EPIC-004's
finding detail (not yet authored); mount the panel there when it lands, and keep it
self-contained here.

## Acceptance

- [x] Automated tab renders the mono command and one `.status-badge` per precondition; Copy plan copies it.
- [x] Manual tab renders the portal path breadcrumb and numbered steps; Copy steps copies them.
- [x] An `undetermined` check renders the triage empty state.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
