# T-0290 — Coverage gaps and per-policy change history

## Report

EPIC-015 SPEC.md §3.1 defines the coverage view: which users/apps are covered by at least one
policy, and the gaps. §4.4 defines coverage computation and change history: history is read from
**directory audits for CA resources** and rendered per policy; §5 adds `CaPolicyChange`
(`id`, `tenantId`, `policyId`, `at`, `by`, `before`, `after`). §6 fixes `GET .../ca/coverage` and
`GET .../ca/history`. §11.4 is resolved to use **both**: directory audits for provenance plus a
portal-side before/after log.

Deliver a read-only `Get-CaCoverage.ps1` + entrypoint and the coverage route, plus the history
route that merges directory audit events (provenance) with the portal's own before/after records
written by T-0282. Build the coverage page, `CoverageView`, and `ChangeHistoryPanel`. Coverage
must identify concrete gaps (users/apps with no policy), not just a count.

## Acceptance

- [x] `GET .../ca/coverage` identifies covered vs uncovered users/apps and concrete gaps.
- [x] `GET .../ca/history` renders per-policy events merging directory audits with portal before/after records.
- [x] The coverage view and change-history panel render from those endpoints.
- [x] Tests cover the route and component and fail without them.
- [x] No file outside `scope` is modified.
